# SEO 子模块权限细化设计

## 背景

当前权限系统把整个 SEO 工具箱作为一个权限项 `SEO工具箱`。页面中的 SEO 工具箱实际上包含多个独立功能，因此无法按用户分别授权。

本次改动把 SEO 工具箱拆分为五项独立权限，同时保留现有的页面层级：正则表达式生成器仍是主标签，GSC 与 GA4 仍是其内部子标签。

## 目标

- 将 SEO 工具箱拆分为五项可独立分配的权限。
- 根据用户权限隐藏对应标签和面板。
- 自动选中用户有权限的第一个功能，避免出现空白面板。
- 让管理后台自动显示新的权限名称。
- 保持现有用户数据结构不变。

## 非目标

- 不启用当前仍处于“待更新”状态的批量收录查询功能。
- 不修改用户密码、登录令牌或 Redis 键名。
- 不把权限数据改成层级对象。
- 不自动迁移任何用户已有的 `SEO工具箱` 权限。

## 权限名称

以下字符串是固定权限标识，必须精确匹配：

1. `外链存活检测`
2. `Dofollow / Nofollow 检测`
3. `GSC URL 正则匹配`
4. `GA4 AI 爬虫正则`
5. `批量收录查询`

`__all__` 继续作为系统保留值，代表拥有全部权限。

旧权限 `SEO工具箱` 不再授予任何 SEO 子模块访问权。

## 页面结构与显示规则

### SEO 工具箱容器

SEO 工具箱容器不再依赖 `data-section="SEO工具箱"` 进行整体授权。它由五项子权限共同决定是否显示：

- 用户拥有任意一项 SEO 子权限时，显示 SEO 工具箱。
- 用户没有任何 SEO 子权限时，隐藏整个 SEO 工具箱。
- 用户拥有 `__all__` 时，显示全部 SEO 功能。

### 主标签

主标签与权限关系如下：

| 主标签 | 显示条件 |
| --- | --- |
| 外链存活检测 | 拥有 `外链存活检测` |
| Dofollow / Nofollow 检测 | 拥有 `Dofollow / Nofollow 检测` |
| 正则表达式生成器 | 拥有 `GSC URL 正则匹配` 或 `GA4 AI 爬虫正则` |
| 批量收录查询 | 拥有 `批量收录查询` |

批量收录查询即使获得权限，也继续显示现有的“暂未开放”状态，不改变其功能可用性。

### 正则表达式子标签

- 只拥有 `GSC URL 正则匹配` 时，只显示 GSC 子标签和面板。
- 只拥有 `GA4 AI 爬虫正则` 时，只显示 GA4 子标签和面板。
- 同时拥有两项权限时，显示两个子标签。
- 进入正则表达式生成器时，自动激活第一个有权限的子标签。

### 默认激活规则

每次登录、恢复登录状态或切换用户后：

1. 重新计算所有 SEO 标签和面板的可见性。
2. 清除之前用户留下的激活状态。
3. 按页面顺序激活第一个有权限的主标签。
4. 如果该标签是正则表达式生成器，再激活第一个有权限的正则子标签。

未知权限名称会被忽略，不影响页面运行。

## 权限数据与后台目录

用户数据结构保持不变：

```json
{
  "pass": "用户密码",
  "sections": ["外链存活检测", "GSC URL 正则匹配"]
}
```

管理后台读取功能模块目录时：

- 如果目录包含旧项 `SEO工具箱`，将其从目录中移除。
- 在旧项原位置加入五项新的 SEO 权限；如果旧项目录中不存在 `SEO工具箱`，则把缺少的新权限追加到目录末尾。
- 保留其他已有模块名称和顺序。
- 对最终目录去重。
- 持久化更新后的功能模块目录。

该目录迁移不修改任何用户的 `sections`。原来只拥有 `SEO工具箱` 的用户需要由管理员重新逐项授权。

## 组件边界

### 页面标记

`app/page.jsx` 负责声明：

- SEO 工具箱容器；
- 主标签与主面板的权限标记；
- GSC/GA4 子标签与子面板的权限标记；
- 正则主标签对两项子权限的聚合关系。

页面标记只描述结构，不自行判断用户权限。

### 权限解析

权限解析逻辑负责把用户的 `sections` 转换成明确的 SEO 可见性状态，包括：

- 是否显示工具箱；
- 哪些主标签可见；
- 哪些正则子标签可见；
- 默认激活的主标签和子标签。

该计算保持为独立、可测试的逻辑，不直接操作 DOM。

### DOM 状态应用

`public/app.js` 负责：

- 将权限解析结果应用到对应标签和面板；
- 隐藏无权限内容；
- 清理旧的激活样式和内联显示状态；
- 激活解析结果指定的默认标签；
- 与现有标签点击事件保持一致。

### 后台目录迁移

管理后台处理器负责迁移功能模块目录。迁移函数保持独立并具备幂等性：重复读取后台不会重复添加权限或改变已迁移结果。

## 错误与边界情况

- `sections` 缺失或不是数组时，按无权限处理。
- `sections` 包含重复值时，按单一权限处理。
- 只有旧权限 `SEO工具箱` 时，隐藏整个 SEO 工具箱。
- 只有 GSC 或 GA4 权限时，正则主标签可见且不会出现空白子面板。
- 没有任何主标签可见时，SEO 工具箱整体隐藏。
- 页面中找不到某个预期元素时，跳过该元素，不阻塞其他权限应用。
- 管理后台目录迁移失败时返回明确错误，不改写用户数据。

## 测试计划

### 权限解析测试

- 单项权限只启用对应功能。
- GSC 单项权限显示正则主标签和 GSC 子标签。
- GA4 单项权限显示正则主标签和 GA4 子标签。
- GSC 与 GA4 同时授权时显示两个子标签。
- `__all__` 启用全部功能。
- 空权限隐藏整个 SEO 工具箱。
- 旧 `SEO工具箱` 权限隐藏整个 SEO 工具箱。
- 未知权限被忽略。

### 管理后台测试

- 功能模块目录将 `SEO工具箱` 替换为五项新权限。
- 迁移可重复执行且不会产生重复项。
- 其他功能模块保持不变。
- 用户已有的 `sections` 不被自动改写。

### 集成验证

- 生产构建成功。
- 现有后台与认证测试继续通过。
- 浏览器分别验证无权限、单项权限、正则单子权限和全部权限场景。
- 检查页面无错误覆盖层、无空白内容，并确认移动端标签仍可使用。

## 发布与回退

发布后，管理员需要为原 `SEO工具箱` 用户重新分配五项新权限。由于旧权限不再兼容，发布前后短时间内这些用户可能暂时看不到 SEO 工具箱。

如果需要回退，只需恢复旧页面权限判断与旧功能模块目录；用户原有 `sections` 未被自动修改，因此不会丢失旧权限记录。
